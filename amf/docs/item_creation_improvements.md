# Item Creation improvement tracker

Updated: 29 October 2026. Evidence: [current existing-head/Product-only audit](item_creation_audit_2026-10-29.md), [28 October audit](item_creation_audit_2026-10-28.md), [original audit](item_creation_audit_2026-10-27.md), [catalogue specification](item_creation_catalogue_specification_2026-10-27.md).

| Improvement | Status | Scope / next action |
| --- | --- | --- |
| Head/component suffix allocation and Product code protection | Implemented and tested | New head families retain matching component suffixes and global reservations. Existing heads may reuse independently numbered enabled components and submitted BOMs. Products have independent codes; existing-head suggestions reuse the matching engineering reference first, then use the head suffix or another available code in the configuration prefix. Explicit overrides and retired-code protection remain. |
| Create Products Only | Implemented and tested | Select an existing head and individual configurations. Preview/review/submit only Product actions; preserve the pinned head/component revisions, even when Product replacements are enabled. Suggested codes appear beside optional editable overrides. |
| Product Reference conflict resolution | Implemented and tested | **Change Product Reference** on the preview error edits that configuration's optional override. Check global/planned uniqueness, retain the selected head identity, show the actual reference in the plan and require fresh engineering review. Existing masters remain preserved. |
| Complete preview and engineering review | Implemented and tested | One read-only plan, exact recipe differences/parent impact, protected review history and dependency-aware stale-review rejection. Reviewed requests/history cannot be deleted through document APIs. |
| Explicit compatibility rules | Implemented and tested | Individual standard body/syringe selections, reference/volume/material identity checks and head-type/LV/HV rules. User-authorized `704000`/`709000` U syringes are supported on all four standard LV bodies. RVM includes base RVM mini `5D1000` / P202-O, with no syringe and Product prefix `4D0`. Other families/interfaces require a reviewed rule update. |
| Complete raw-material BOMs | Implemented and tested | Exact stock selection, positive reviewed consumption and current stock UOM for every newly machined component. User-requested editable defaults: seat `0.03`, plug `0.02`. Five Items/five BOMs for a complete new head. |
| Selectable seat pins | Implemented and tested | Enabled Item selector plus existing pin quantity; defaults to `SPL.3039`. Selected Item, quantity and dependencies participate in engineering review. |
| Guided form and accurate previews | Implemented and tested | Full-width configuration table, explicit RVM mini/LV/HV/HD chooser labels and visible head requirements. Code-based Body (`5_1___`) and Syringe (`70X___`, X a digit 1–9 or a letter) selectors, complete shared plan, safe rendering, stale-response handling and live errors. |
| Simpler execution and performance | Implemented and tested | Pure shared recipes, bulk/cache-limited dependency reads, pinned BOM revisions and request-owned transactions without monkey-patching database methods. Existing dependency chains are validated once per Item/BOM revision; Product inventory/reservations are read once per plan. |
| Formal application-wide permission policy | Proposed | Retain existing authorized roles for this work; audit other helpers and define broader role separation separately. |
| Structured engineering specifications | Partly improved; further work proposed | Safe ordinary/custom-name handling, compound channel descriptions and contextual material names implemented. Dedicated geometry/material fields remain proposed. |
| Versioned engineering recipe templates | Foundation implemented; further work proposed | Versioned code rules and recorded per-request approval implemented. A maintained engineering-template DocType and its own release workflow remain proposed. |
| Traceability and lifecycle | Implemented and tested | Immutable result child rows, Item/BOM reverse links and a permission-filtered results report. Reasoned cancellation retains generated records/reservations; one active amendment per predecessor reuses its head family and requires fresh review. Retirement stays a separate engineering decision, as requested. |
| Company-wide defaults and costing policy | Partly implemented | Explicit company/warehouse validation and removal of guessed component valuation seeds implemented. Broader settings/costing policy remain separate. |
| Historical catalogue corrections | Proposed | Review the 37 earlier Product/head disagreements and engineering exceptions. Reuse now reports consistent old stock-UOM labels for engineering review without rewriting submitted revisions. Missing BOMs, invalid quantities and inconsistent conversions remain blockers; no automatic data repair. |
| Quotation discovery of custom Product references | Proposed | The composition selector currently searches the generated reference and its code fallback. Add discovery from actual BOM composition for independently numbered Products with custom references; direct Product selection by Item Code remains available. |
| Platform migration | Proposed | Separate migration project for the patched v12 application and its dependencies. |

Traceability extension: [result links and lifecycle policy](item_creation_traceability_2026-10-27.md). AMF `0.7.3` adds a registered additive migration and indexes only existing recorded execution JSON. Ordinary approval hashes and recipe execution remain compatible. A real rollback-only case created seven Items/seven submitted BOMs, retained them on cancellation, and submitted two replacement BOMs through a fresh amendment review in about 12 seconds. Direct result edits/deletion and duplicate active amendments were rejected; old/new revision searches and repeated result backfill passed.

Traceability release verification: 132 focused/regression Python tests, 15 read-only site regression tests and the expanded form/reverse-link Node tests passed. Live digit/letter syringe queries and Guest denials passed in a read-only transaction. An injected failure after writing all seven result links propagated and rolled back Items, BOMs, requests, result rows, reservations and QR files.

AMF `0.7.4` selector clarification: the third character must be 1–9 or a letter, excluding `0`. Live read-only checks verified `700025` is excluded and `709000`/`70E000` are included; 34 focused Python tests and the form tests passed. This code-format filter is separate from the compatibility matrix. The omission of U syringes `704000`/`709000` was inferred from disabled historical Products, not a demonstrated physical incompatibility. That restriction is superseded by the user's authorization implemented in `0.7.5` below.

AMF `0.7.5` LV/U extension: per explicit user instruction, rule version `2026-10-27.2` permits both enabled U syringes `704000` (`S-100-U`) and `709000` (`S-500-U`) on `551000`, `571000`, `591000` and `5B1000`. The chooser, preview and execution share these eight added combinations. U reference identity, enabled-Item checks, standard D/DS geometry and engineering review remain enforced; HV support is unchanged. Earlier draft approvals require refresh/review because the rules changed. No historical Product is reactivated, and no schema migration is needed for this code-only extension.

LV/U release verification: 136 focused/regression Python tests, 15 read-only site regression tests and guided-form Node checks passed. The chooser, generated codes, exact U references and consumed Body/Syringe quantities were verified. Temporary Items, BOMs, results, reservations and QR files were rolled back; internal commits were prohibited. The expanded maximum standard plan now contains 35 Items/BOMs and passed the bulk-read unit check.

AMF `0.7.8` implements existing-head component reuse and **Create Products Only**. New heads/components remain a matching suffix family. Changing an existing head's selected parts requires **Propose Replacement BOMs** and a fresh review; reusing its actual parts does not. Product suggestions check enabled matches by the globally unique engineering reference, canonical Item/retired aliases and exact member reservations. They retain the configuration prefix, prefer the head suffix when available, then search decimal and alphanumeric suffixes. An existing matching Product keeps its Item name/reference; no master is renamed or reactivated. Plan version `4` requires refreshing/reviewing earlier draft approvals while retaining historical snapshots.
